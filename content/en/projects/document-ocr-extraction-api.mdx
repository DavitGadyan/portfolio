## The problem

Sick.org / Curogram helps patients book doctors and tests. Every booking comes with documents, typically a driver licence and an insurance card, whose details had to be typed into Curogram's system by hand. As the user base grew, manual entry could not keep up with the volume of requests, so the client needed an algorithm that reads the documents and returns the fields.

## What I built

- A prototyping round that compared two families of approach: OCR followed by an NLP model that extracts custom labels, and a computer-vision model that detects each field (name, address, gender and so on) directly on the image.
- Custom detection models trained with YOLO, alongside AWS Textract, Comprehend and Rekognition, to see which combination worked for the client's documents.
- The production extractor: AWS Textract for OCR, with regular expressions that pull the required details out of driver licences and insurance cards.
- A REST API wrapping the extractor so Curogram's system can send an image and receive structured fields back.

## How it was delivered

The deciding factor turned out to be latency. The YOLO and OCR-plus-NLP prototypes took around 10 seconds per image, too slow for a booking flow that processes large volumes. Textract plus regex came in under 5 seconds, so I shipped that path, deployed it as a REST API and kept the heavier models out of the critical path.

## Outcome

Document data entry at Sick.org / Curogram went from a manual step to an API call that returns the fields from a driver licence or insurance card in under 5 seconds. The service absorbs the growing volume of requests, and the simpler approach won on speed.
