## El problema

El cliente quería dos cosas para el mercado inmobiliario australiano: un modelo que prediga el precio de un inmueble con la mayor precisión posible, y un bot que evalúe una propiedad como lo haría un agente inmobiliario experimentado, para encontrar la operación que dé el mayor beneficio. Ninguna de las dos existía, y ambas dependían de datos inmobiliarios que primero había que recopilar.

## Qué construí

- Una capa de recopilación de datos que obtenía anuncios a través de API como la [API para desarrolladores de Domain.com.au](https://developer.domain.com.au/) y extraía datos adicionales directamente de portales inmobiliarios mediante scraping.
- Ingeniería de características sobre los anuncios recopilados para convertir los registros brutos de inmuebles en entradas del modelo.
- Un modelo de regresión XGBoost, elegido tras compararlo con otros algoritmos sobre los mismos datos; superó a las alternativas.
- Un prototipo del algoritmo de evaluación del agente, implementado a partir de la descripción del cliente de cómo un agente valora un inmueble para obtener el máximo beneficio.

## Cómo se entregó

La primera etapa fue el modelo de valoración. Mi métrica objetivo era el R², y el modelo XGBoost final alcanzó en torno al 84 %, un resultado sólido para este caso de uso. La segunda etapa fue el bot del agente: el cliente compartió la lógica de evaluación, construí el prototipo y empecé a probarlo. La versión alfa tiene todas las funciones implementadas; lo que todavía necesita son datos suficientes para cubrir todas las combinaciones de entradas que el algoritmo puede pedir.

## Resultado

Un modelo de valoración automatizada con un R² en torno al 84 % para precios de inmuebles australianos, construido sobre datos que recopilé mediante la API de Domain.com.au y web scraping, y una alfa completa en funciones del bot del cliente para maximizar el beneficio. El trabajo pendiente es cobertura de datos, no código.
